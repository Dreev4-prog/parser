# Kleinanzeigen Parser Bot v2.6.4

## Что нового

### Выбор глубины при каждом запуске
После нажатия **▶️ Начать парсинг** бот обязательно спрашивает, сколько страниц обновить в каждой выбранной категории:

- **25 страниц** — быстрый сбор;
- **50 страниц** — средняя глубина;
- **100 страниц** — максимальная глубина.

100 страниц остаются жёстким верхним пределом безопасности. Выбор сохраняется как последний использованный, но при следующем запуске бот всё равно спрашивает глубину заново.

### Более реалистичный ETA
Пользователь больше не видит оптимистичные оценки вроде «осталось 15 секунд» в начале длинного прохода.

Начальная консервативная оценка на одну реально сканируемую категорию:

- 25 страниц → около **1 минуты**;
- 50 страниц → около **2 минут**;
- 100 страниц → около **3 минут**.

После первых нескольких страниц ETA пересчитывается по фактической скорости обработки страниц и постепенно уточняется. В интерфейсе оставшееся время показывается в минутах (`≈ 3 мин`, `≈ 2 мин`, `меньше 1 мин`), без ложной секундной точности.

Во время запуска пользователь видит:

```text
🔄 Парсинг идёт

███░░░░░░░ 30%
Категории: 0/1 готово
Глубина: 100 страниц
Сейчас: Konsolen
Страница: 30 / 100
Объявлений просмотрено в категории: 742

🆕 Найдено новых: 188
⏱ Прошло: 1 мин
⌛ Осталось примерно: ≈ 2 мин
```

### Кэш учитывает выбранную глубину
Если недавно был собран только диапазон в 25 страниц, запрос на 100 страниц не считается полностью покрытым кэшем. Бот углубит сбор. Если же категория уже полностью собрана за текущий день или ранее сегодня была покрыта на нужную глубину, Fast Incremental/кэш продолжают работать.

### Multi-user Core остаётся
Внутри сохраняются очередь, ограничение параллельных задач, общий кэш категорий и объединение одинаковых одновременных сканов. Пользователь при этом видит только собственный живой прогресс, без технической информации о воркерах и общей очереди.

После завершения бот автоматически отправляет итог и готовый файл результата.

## Railway

Новый проект создавать не нужно. Замените файлы в текущем GitHub-репозитории и дождитесь redeploy.

Start Command:

```bash
python bot.py
```

Обязательные переменные:

```env
BOT_TOKEN=...
ADMIN_IDS=123456789
```

Рекомендуемые текущие значения:

```env
MAX_PAGES_PER_CATEGORY=100
PAGE_DELAY_SECONDS=0.7
MAX_CONCURRENT_JOBS=3
MAX_QUEUE_SIZE=200
CATEGORY_CACHE_TTL_SECONDS=300
STATUS_UPDATE_INTERVAL_SECONDS=1.5
```

Даже если `MAX_PAGES_PER_CATEGORY` окажется выше 100, код всё равно не проходит больше 100 страниц одной категории.

## Важно

- Парсер работает только с публичными страницами Kleinanzeigen.
- Обход CAPTCHA, авторизации или механизмов контроля доступа не реализуется.
- До PostgreSQL очередь и часть состояния остаются привязаны к одному процессу Railway/SQLite и могут потеряться при redeploy/restart.
