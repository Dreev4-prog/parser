# DT Parser v4.23.6 — Radar Idle Turbo + Exact Repair

**Base:** v4.23.5 Vinted Lab Instant Navigation.

Этот релиз ускоряет именно основной **Kleinanzeigen DT Radar 3.2 / AutoScan** и уменьшает число категорий, которые уходят в `⚠️ допроверка` из-за неполного сбора точных просмотров.

## Почему круг оставался долгим

На реальном круге было видно примерно `54870 / 55945` точных просмотров: более тысячи счётчиков остались UNKNOWN. При этом системных ошибок было `0`, но 24 категории ушли в допроверку.

До v4.23.6 после основного View Worker прохода + direct salvage большой остаток UNKNOWN не ремонтировался локально: точный tail-retry был разрешён только до 12 URL. Категория с большим хвостом fail-closed попадала в повтор, а кнопка повтора снова прогоняла всю категорию.

## 1. Idle Turbo — свободные ресурсы отдаём Radar

AutoScan теперь проверяет, есть ли обычные пользовательские сканы в работе или очереди.

Если пользователей нет и Traffic Manager не находится в 403/429 penalty/cooldown:

- локальная exact-view concurrency поднимается до **x8** (в пределах доступного view pool);
- rolling Page Worker prefetch расширяется до **20 страниц**, поэтому 4 Page Worker могут заранее прогреть почти всю текущую категорию;
- дополнительный ремонт UNKNOWN разрешён только в этом idle-режиме.

Если появляется пользователь:

- новые Turbo-операции больше не запускаются;
- дальнейшие repair-chunks прекращаются на ближайшей границе;
- обычная пользовательская очередь остаётся главным приоритетом;
- параллельный запуск нескольких полных AutoScan-категорий **не добавлен**, чтобы Radar не мог забрать все ресурсы у людей.

## 2. Большой exact tail больше не означает немедленный полный rescan

После основного exact-view прохода v4.23.6 работает так:

1. уже подтверждённые exact counters сохраняются;
2. UNKNOWN получает дешёвый official-counter salvage;
3. если хвост всё ещё больше 12, но не больше 256 и бот свободен — только UNKNOWN URL получают второй проход через View Worker fleet;
4. после него выполняется ещё один cheap direct salvage;
5. оставшийся небольшой хвост до 32 URL в idle-режиме проходит accurate repair маленькими chunks;
6. только если после этого категория всё ещё не проходит прежний quality gate, она остаётся в `⚠️ допроверка`.

То есть сотни уже успешно проверенных объявлений больше не открываются повторно только из-за нескольких десятков временных промахов.

## 3. Точность не ослаблена

Не менялись:

- минимальное exact coverage: **99%**;
- soft UNKNOWN tail: максимум **8**;
- UNKNOWN никогда не превращается в `0`;
- неполная категория по-прежнему fail-closed;
- никаких приблизительных просмотров не используется;
- Organic / DT Score / baseline правила не ослаблены.

## 4. Теперь видно, почему категории ушли в допроверку

Главная карточка AutoScan показывает breakdown:

- `👁 views` — неполные точные просмотры;
- `📄 pages` — страничная/хронологическая неполнота;
- `⏱ watchdog` — category watchdog;
- `🔒 gate` — UNKNOWN на Organic Gate;
- `❓ другое` — остальные retryable причины.

Для уже сохранённого круга v4.23.5 breakdown восстанавливается из `failed_categories`, поэтому после deploy можно увидеть причину старых 24 допроверок без нового полного круга.

Во время активного круга карточка также показывает:

- `⚡ Ресурсы: Idle Turbo ...` когда Radar использует свободную мощность;
- `🛡 Ресурсы: приоритет пользователей ...` когда есть пользовательская нагрузка или traffic penalty.

## Railway

Обязательных новых variables нет.

Опциональные overrides (по умолчанию уже настроены):

```text
RADAR_AUTOSCAN_IDLE_TURBO_ENABLED=1
RADAR_AUTOSCAN_IDLE_VIEW_CONCURRENCY=8
RADAR_AUTOSCAN_IDLE_REMOTE_RETRY_MAX=256
RADAR_AUTOSCAN_IDLE_REMOTE_RETRY_SECONDS=45
RADAR_AUTOSCAN_IDLE_VIEW_REPAIR_MAX=32
RADAR_AUTOSCAN_IDLE_VIEW_REPAIR_CHUNK=16
RADAR_AUTOSCAN_IDLE_PREFETCH_PAGES=20
```

Для быстрого rollback Turbo без отката кода:

```text
RADAR_AUTOSCAN_IDLE_TURBO_ENABLED=0
```

## Deploy

Патч накладывается **поверх v4.23.5**.

Достаточно redeploy:

- **Parser / Bot** — обязательно.

Page Worker / View Worker код этим патчем не меняется. Их существующие реплики автоматически получают больше работы от Parser, когда бот свободен.

SQL-миграций нет.
