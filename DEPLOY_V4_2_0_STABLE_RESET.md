# DT PARSER v4.2.0 — Stable Reset

Цель версии: вернуть простой и предсказуемый однопоточный парсинг, не затрагивая пользовательский функционал.

## Что изменено

- Один встроенный scan worker. Второй пользователь ждёт локальную очередь.
- Redis не участвует в запуске/выполнении интерактивного скана. Его можно оставить подключённым.
- Кэш готового результата категории отключён в baseline; используются только короткие verified-page checkpoints PostgreSQL.
- Основной транспорт — обычный Chromium browser context.
- Убраны повторные полные проходы категории.
- Проблемная страница повторяется точечно; после обычных повторов выполняется один чистый recycle browser session и последняя попытка этой же страницы.
- Убран ложный anti-bot marker `robot`, который совпадал с Mähroboter/Saugroboter.
- В логах для `valid=False` теперь выводится `invalid_reason`.
- Подтверждённые страницы по-прежнему checkpoint'ятся в PostgreSQL и переживают рестарт Railway.
- Просмотры остаются отдельной фазой после сбора страниц.

## Railway

Start Command остаётся:

```text
python bot.py
```

Новые переменные не обязательны. По умолчанию `STABLE_SINGLE_SERVICE_MODE=1`.
`REDIS_URL` можно оставить — он не включает Browser Fleet в этой версии.

Ожидаемый startup log:

```text
v4.2.0 Stable Reset active | parser_lane=1 | transport=browser | redis_in_scan_path=False
```

Когда один parser lane будет стабилен на серии тестов, параллель вернём отдельными worker-сервисами без изменения алгоритма парсинга.
