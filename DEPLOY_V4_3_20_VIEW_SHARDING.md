# DT PARSER v4.3.20 — VIEW SHARDING

## Что изменилось

Большой замер просмотров теперь может использовать несколько Railway View Worker replicas одновременно.

До v4.3.20 один вызов `RemoteViewManager.fetch()` создавал один Redis job, поэтому целый замер мог полностью выполнять только одна реплика.

В v4.3.20 основной бот:

1. Проверяет количество живых View Worker replicas.
2. Если живых worker меньше двух — оставляет прежний single-job путь.
3. Если worker 2+ и в замере не меньше 300 URL — разбивает его на независимые shards.
4. По умолчанию целевой размер shard около 250 URL и минимум 2 shards на каждый обнаруженный worker.
5. Все shard jobs одновременно кладутся в общую Redis Stream consumer group.
6. Готовые результаты объединяются обратно в один словарь в исходном порядке URL.
7. Общий прогресс складывается из прогресса всех shards.
8. Если любой shard требует fallback — остальные shard jobs отменяются, а бот запускает прежний локальный v4.3.8 fallback. Частичный remote-результат успешным не считается.

## Настройки по умолчанию

Ничего добавлять в Railway Variables не требуется.

```text
VIEW_SHARDING_ENABLED=1
VIEW_SHARD_MIN_URLS=300
VIEW_SHARD_SIZE=250
VIEW_SHARD_MAX_COUNT=16
VIEW_SHARDS_PER_WORKER=2
```

Эти переменные можно добавить позже только для ручного тюнинга.

## Почему две реплики теперь используются одним сканом

При двух живых worker большой batch создаёт минимум 4 shard jobs. В v4.3.18 каждая реплика допускает максимум 2 активных jobs, поэтому одна реплика не может забрать все четыре: оставшиеся jobs доступны второй реплике.

Пример для 1000 URL:

```text
1000 URL
  -> shard 1 ~250
  -> shard 2 ~250
  -> shard 3 ~250
  -> shard 4 ~250

View Worker #1: до 2 shards
View Worker #2: до 2 shards
```

## Админ-панель

`👁 View Worker` дополнительно показывает:

- включён ли View Sharding;
- целевой размер shard;
- сколько URL было в последнем remote batch;
- на сколько jobs он был разбит;
- сколько живых workers менеджер видел в момент запуска.

## Первый тест

Рекомендуемый первый тест после деплоя:

- 1 скан;
- несколько категорий;
- 50 страниц;
- открыть `Админ-панель -> 👁 View Worker` во время сбора просмотров.

Для крупного view batch должны одновременно появиться активные jobs на обеих репликах.
