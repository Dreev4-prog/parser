# Audit 4.21.12 — Radar 3.2 Two-Pass Clean

## Problems found and fixed
1. 4.21.11 still shipped stale 15/30/60 contract tests; full pytest was not green.
2. Category-adaptive scoring was order-dependent inside a refresh batch because thresholds were recalculated while rows were being processed.
3. User scans could still seed Auto/Immobilien/Jobs/Services and other excluded groups back into Radar.
4. Old persisted AutoScan progress/history/counters could survive a category-policy change and confuse the new dashboard.
5. Adaptive dashboard funnel counted percentile alone; in small cohorts a row could be shown as Candidate even when the conservative fallback gate left it quiet.
6. Runtime/docs still contained mixed Radar 3.1/3.2 labels.

## Fixes
- Two-pass refresh: persist all measured VPH first, then calculate one category cohort and thresholds for the entire batch.
- Canonical `radar_v3_category_allowed()` policy shared by AutoScan and user-scan baseline seeding.
- New reset marker `dt_radar_v3_observed_demand_reset_v6_radar32_two_pass_clean` clears Radar output/evidence tables once while preserving raw Listing/ViewHistory.
- AutoScan policy v6 discards old telemetry/progress/history while keeping daily schedule preferences.
- Dashboard counts evaluated `candidate/observed/confirmed` states rather than percentile alone.
- Full contract suite updated for P90/P95/P98/P99 semantics.

- Release smoke: PASS.
- RadarObservation/RadarProduct ORM reference scan: no unknown fields.
- Admin Radar callback coverage: all literal control callbacks have handlers.
