# DT PARSER v4.2.2 — Accurate Views Core

Цель версии: просмотры снова являются доверенным сигналом для `50+ / 100+`, TOP и замеров +3/+6/+12ч.

## Что изменено

- Массовый сбор просмотров больше не принимает любой `200 OK` от `s-vac-inc-get.json` за правильный счётчик.
- По умолчанию каждый счётчик проверяется через публичную страницу объявления в Chromium.
- Источник истины: видимый DOM-счётчик (`#viewad-cntr-num` / `view-count` / публичный extra-info). Сетевой ответ используется только как fallback и только если содержит явно названное поле views/viewCount/Aufrufe/counter.
- `count`, `num`, `value`, `impressions`, `visits` и голые числа не считаются просмотрами.
- Если значение не удалось подтвердить, сохраняется `None`/`👁 —`, а не `0` и не старое значение. Такое объявление не проходит фильтр 50+/100+ и не попадает в TOP как будто счётчик известен.
- Прогресс обновляется в реальном времени.
- Старый 30-минутный кэш не используется для рейтинговых замеров. Допускается только короткое <=60 секунд совместное использование уже проверенного значения, чтобы мгновенный baseline не открывал те же сотни объявлений повторно.
- Первый запуск v4.2.2 один раз сбрасывает старые недостоверные view_count и историю приростов. Сами объявления и сканы не удаляются.
- Старые незавершённые сканы после Railway restart больше не воскресают автоматически и не создают новые Telegram-карточки.
- В Stable Single Service у пользователя может быть только один незавершённый scan_id.

## Railway

Start Command не меняется:

```text
python bot.py
```

Новых обязательных Variables нет. По умолчанию:

```text
ACCURATE_VIEWS_MODE=1
ACCURATE_VIEW_BROWSER_CONCURRENCY=2
ACCURATE_VIEW_RETRIES=2
```

Для первого теста не увеличивать concurrency: сначала сверить 20–30 объявлений вручную с сайтом.
